추가 발견·수정:

- **큰 배 승선 통로 단절:** 실제 x=-3.3 경로가 z=2.1, 높이 0.84에서 난간에 걸리고, 후진 시 z=1.6 물 틈에 떨어져 통로 복귀가 막혔다. 실제 JSX 기반 무점프 검사에서도 같은 좌표로 재현했다. 연결판을 연장하고 난간을 넘는 낮은 계단을 추가했다. x=-3.3/-3.2/-3.1 세 경로에서 점프 없는 승선·부두 복귀 검사를 통과했다. **이 추가 수정의 실제 브라우저 왕복은 아직 미검증이다.**
- 작은 화면에서 숨겨지던 탐험 설명을 `탐험 안내` 접이식 패널로 읽을 수 있게 했다. 넓은 PC에는 기존 안내를 유지한다. `수면 2단 도약 ↑`의 어색한 줄바꿈을 `수면 도약 ↑`로 정리하고 2회 입력 설명은 상태 안내에 유지했다.
- 공유 스킬에 계단/승선 통로 무점프 왕복과 좁은 화면의 안내 접근 기준을 반영했다.

아래 자동 경로 JSON은 승선 통로 추가 수정 전의 최초 64개 검사 증거다. 승선 통로 수정 후에도 전체 경로 검사를 재실행했으며, 새 무점프 왕복 검사를 추가했다. 완료 범위를 20개 실제 목적지 왕복으로 확대해 해석하지 않는다.

최신 검증: 전체 자동 테스트 **65개 통과**, 생략 없음(원본 경로 지정). 운영 빌드 성공. 스킬 검증 및 `git diff --check` 통과. 기존 번들 크기/Firestore 혼합 import 경고는 남아 있다. commit/push 및 운영 배포는 하지 않았다.

### 최초 확대 검사 이력 (새 창 재개 전)

- 실제 장면 메시와 운영 물리/미끄럼틀 흐름을 이용한 20개 연속 왕복 경로 통과.
- 이름 붙인 목적지/경유 지점 102개와 각 월드의 출발점 복귀 확인. 모든 장식 메시를 개별 발판으로 검수했다는 뜻은 아니다.
- 전체 자동 테스트 64/64 통과, 생략 0. 최종 소스 빌드 성공.
- Chrome 실제 조작을 재개했으나 긴 누름·클릭·작품 선택·이후 이동에서 반복적인 도구 응답 시간 초과와 느린 화면 갱신이 발생했다. 해변 일부 이동/점프까지만 관찰했으며, 안정된 착지를 확정하지 않았다. 브라우저 실제 목적지 왕복 20개 완료로 기록하지 않는다.
- 검수 탭을 다시 확보하고 문서화된 짧은 키 입력 등 대안을 시도했지만 안정적으로 진행할 수 없었다. Chrome 창이 최소화된 경우 띄워 달라고 사용자에게 요청했다. 최소화가 원인이라고 확정한 것은 아니다.

2. **제작 19 / ID18 분화구 테두리:** 기존 Solid가 rotation을 전달하지 않아 테두리가 수평으로 놓이지 않았고 고정 높이로 지면과 어긋났다. 테두리 메시를 실제 달 곡면에 맞췄다. 원본 start.jpg를 확인했으며, 달 지면과 테두리 생성이 같은 높이 함수를 공유한다. 세 주요 테두리에 지면보다 높은 안정 착지와 복귀를 검사했다. 최종 렌더 재검수는 브라우저 연결 회복 후 필요하다.
3. **안내와 지도:** 즐거운 워터파크의 계단은 뒤쪽 마른 바닥이 아니라 앞쪽 물에서 진입하므로 안내와 입구 좌표를 정정했다. 워터파크 수영장의 노란 상단 표식, 수박 튜브 표식도 실제 물체 위치로 맞췄다.

## 검사 방법과 한계

- 한 월드당 최초 spawn에서만 시작한다. 이후 점 사이에 순간이동하거나 위치·높이·점프 횟수를 초기화하지 않는다.
- 걷기/수영 속도, 중력, 2단 점프와 충돌, 미끄럼틀의 강제 이동을 운영 함수로 계산한다.
- 목적지 반경, 최소 발판 높이, 수직 속도 0, 점프 재충전 상태를 동시에 만족해야 도착이다. 미끄럼틀 통과 지점은 흐름 때문에 정밀 한 점 정차가 불가능하므로 명시한 .8~1.2 반경을 사용한다.
- 이름의 '기단/처마' 검사는 최소 높이 이상 도착이며 정확히 그 층에 따로 정차한다는 뜻은 아니다. 다보탑은 실제 결과에서 상층을 거쳐 꼭대기까지 도달했다.
- 테스트 입력은 경로를 아는 자동 조작이다. 학생이 안내만 보고 길을 알아내는지, 화면이 가리는지, 실제 키·터치 입력이 편한지는 별도 브라우저 검수 항목이다.
- 정적 JSX 구조를 생성할 때 인물/텍스처/React 훅을 대체한다. 동적 인물 애니메이션과 렌더 품질을 이 테스트로 보증하지 않는다.
- 전체 목적지 브라우저 왕복, 모든 발판 측면/머리 충돌, 모바일 멀티터치를 완료로 표시하지 않는다.

## 이어서 할 일

Chrome의 긴 입력이 안정된 상태에서 큰 배 연결판 수정 후 실제 왕복부터 재검수 → 남은 목적지 경로 검사 → 발견 오류 수정 및 회귀 검사 → commit/push → Vercel Ready와 운영 주소 확인. 성 상단과 분화구 대표 렌더 확인은 위 재개 결과까지 완료했다. 사용자가 배포를 요청했으므로 다시 배포 승인을 묻지 않는다.
